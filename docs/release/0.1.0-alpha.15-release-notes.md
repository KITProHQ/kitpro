# KITPro Server v0.1.0-alpha.15

## Native Linux Host Administration

Alpha.15 adds native Linux host administration to KITPro Server while preserving the application catalog, Docker lifecycle, managed ingress, HTTPS, diagnostics, backup and recovery, and administrator recovery workflows.

### Highlights

- Unified Administration Dashboard with bounded system-health summaries.
- Host Overview for operating-system, kernel, CPU, memory, filesystem, and network information.
- Compact systemd Services and journald Logs interfaces designed for large administrative datasets.
- Curated, action-specific service management with dependency protection, scoped administrator permissions, exact confirmation, operation history, and durable auditing.
- Storage inventory for block devices, filesystems, mounts, utilization, and protected resources.
- Controlled mount and unmount operations for exact policy-approved resources.
- KITPro-managed persistent systemd mount units with UUID validation, atomic publication, recovery records, and missing-device boot protection.
- Network interface, address, route, resolver, traffic, and diagnostic visibility.
- Transactional IPv4 configuration for exact policy-approved systemd-networkd resources, with an independently armed rollback timer and explicit confirmation.

The API remains unprivileged. Approved mutations pass through the typed KITPro helper, which verifies its Unix peer and independently revalidates authorization, policy, identity, current host state, and confirmation data.

## Platform status

- **Supported and installed-service qualified:** Ubuntu 26.04 LTS amd64.
- **Supported and installed-service qualified:** KITPro Linux Server generation `1.0-g0002`, using the separately controlled signed package-generation process.
- **Package and provider support:** Debian 13 amd64 and supported Arch-family x86_64 systems.
- **Experimental:** Rocky Linux 10 amd64 with Podman 5 and SELinux. The RPM and SELinux packages pass static and reproducibility checks, but complete installed Host Administration qualification has not been established on Rocky Linux.

## Safety boundaries

Alpha.15 does not provide unrestricted host control.

- Service mutations remain limited to the curated, action-specific catalog. Protected, unknown, ambiguous, or incompletely analyzed units remain read-only.
- Journal access is disabled by default and still requires operating-system journal permission when enabled.
- Storage mutations require a root-owned exact-resource policy. Qualification used disposable tmpfs and UUID-backed loopback filesystems; it does not establish mutation safety for arbitrary physical disks, RAID, LVM, ZFS, formatting, resizing, forced unmount, or `/etc/fstab` editing.
- Persistent mounts are limited to KITPro-owned systemd mount units. Existing administrator-managed mount configuration is not adopted or rewritten.
- Network mutation is limited to exact approved systemd-networkd resources. Primary management interfaces, NetworkManager and Netplan mutation, IPv6 mutation, bridges, bonds, VLANs, VPNs, firewalls, arbitrary routes, and Docker networking remain unavailable.
- Unknown identity, ownership, dependency, backend, recovery, or resulting state fails closed.
- Package downgrade after a schema migration is unsupported. Use the verified preflight backup or guest recovery snapshot.

## Installation and upgrade

Use the package and upgrade wrapper for your platform. Docker or Podman, Nginx, systemd, and the platform security prerequisites must be available as described in the installation documentation.

Before installation, download `kitpro-server-0.1.0-alpha.15-SHA256SUMS` and verify the selected artifact:

```text
sha256sum -c kitpro-server-0.1.0-alpha.15-SHA256SUMS --ignore-missing
```

The Debian and Arch upgrade gates preserve existing configuration and administrator state, validate package ownership and schema transitions, create pre-upgrade backups, and fail closed when preflight requirements are not met.

KITPro Linux installation also requires a production-signed immutable dependency generation. The GitHub prerelease does not publish or advance that Linux repository generation.
