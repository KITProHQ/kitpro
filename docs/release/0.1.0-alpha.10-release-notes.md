# KITPro Server 0.1.0-alpha.10 release notes

Alpha 10 adds administrator-approved external storage without adding arbitrary
Docker bind mounts. Administrators register existing local or host-mounted NAS
directories in **Settings > Storage**. Trusted application manifests request a
logical slot, and users select a compatible registered location during install.

The helper records canonical path, filesystem, mount source, mount point,
device identity, and root inode. It rejects protected host paths and symbolic
link aliases. Missing or changed required storage blocks start and recreation;
unexpected mounts and read-only-to-read-write changes reconcile as security
drift.

Jellyfin 12.1 joins the trusted catalog with managed configuration and cache,
one required read-only media library, HTTP 8096, and private-by-default
exposure. Imported media remains outside KITPro's data lifecycle and is not
deleted with the application or included in control-plane backups.

Syncthing remains excluded because its complete supported LAN topology needs
UDP services or host networking. Immich remains excluded because its supported
multi-container, database, machine-learning, and read-write photo lifecycle
need a larger acceptance milestone.

See [the trusted storage guide](../trusted-storage.md), [architecture](../architecture/trusted-storage.md), and [known limitations](known-limitations.md).
