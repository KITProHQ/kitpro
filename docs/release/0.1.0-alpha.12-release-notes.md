# KITPro Server v0.1.0-alpha.12 release notes — draft

This is a draft for the proposed next public alpha. It is not evidence that a
tag, package, or release has been published.

## Reliability

- Application replacement now prepares and verifies a new runtime generation
  before committing it as active.
- The previous working generation is retained stopped when recovery may need
  it. Cleanup failure is recorded separately from a successful cutover.
- Multi-component applications persist their dependency topology, start
  dependencies before dependents, stop in reverse order, and record progress
  for each component.
- Privileged mutations use durable semantic operation IDs, canonical request
  hashes, per-installation leases, and fencing. Exact replay returns the
  existing result; conflicting ID reuse is rejected.
- Helper interruption, API response loss, and unknown runtime outcomes enter
  reconciliation instead of blindly repeating destructive work.

## Reconciliation and repair

- KITPro records runtime state separately from reconciliation state and desired
  state.
- Fresh reconciliation detects missing, stopped, drifted, unavailable, or
  cleanup-pending runtime generations and stale control projections.
- Bounded repairs can start an exact stopped generation, recreate a missing
  generation from trusted state, clean exact non-active resources, or
  acknowledge a missing retained generation.
- A running container is not described as application readiness unless a
  future trusted manifest supplies an explicit readiness check.

## Backup and restore

- Application restore now journals path identity, swap progress, generated
  secrets, prior runtime state, and cleanup debt before cutover.
- Startup recovery can complete a proven forward state, roll back to the prior
  tree, or stop with action required when mixed state cannot be resolved safely.

## Migration and packaging

- Existing public alpha.11 schema-7 control and helper databases migrate to
  schema 13 without discarding legacy receipts or ownership evidence.
- Debian 13 and Arch Linux package install, upgrade, reboot, removal,
  reinstallation, AppArmor/systemd confinement, and reproducibility passed VM
  acceptance for the release-candidate source tree.
- Arch upgrades fail before package files change when an existing database
  cannot be verified and backed up. The alpha.11 bootstrap uses a checksummed
  wrapper; alpha.12 installs the permanent pacman pre-transaction hook.
- Debian package configuration reloads the systemd manager before restarting
  services. The Arch source builder ignores paths deleted from the validated
  working tree.

## Known limitations

- KITPro Server remains alpha software.
- Debian 13 and Arch Linux are the public baseline. Ubuntu evidence is
  development-only. Rocky Linux and Podman remain Experimental.
- Runtime-running state is not application readiness.
- Same-port replacement has a bounded cutover interruption.
- Failed restore trees can require an explicit retention or cleanup decision.
- KITPro does not provide arbitrary Compose, generic container management,
  host-to-host restore, or rollback of irreversible application data migrations.
